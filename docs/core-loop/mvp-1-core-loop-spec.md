## 1. MVP-1 设计目标

### 1.1 头号假设：放置节拍

MVP-1 的唯一核心目标是验证以下节拍是否成立：

```text
离线收益 → 回归检查 → 决策投入
```

**文档依据**：MVP-0 规格书 §1.2 特别声明原文——

> 「放置节拍是尚未验证的第二核心假设：MVP-0 是一个 30–60 分钟的**主动**循环验证，完全不包含离线收益与回访节奏。『离线收益 → 回归检查 → 决策投入』的放置节拍是独立假设，MVP-0 通过**不构成**该假设成立的证据（**等 2 分钟资源与隔 8 小时回访是两种不同的心理模型**），该假设由 MVP-1 的基础离线收益单独验证。」

同口径见 MVP-0 规格书 §10.3（放置/离线节拍列为「MVP-0 不用验证的指标」）与量级边界文档「节奏模型」行（「离线/回访节拍是品类核心；属独立假设，归 MVP-1 单独验证」）。

### 1.2 假设边界（防止验证目标漂移）

- **验证的是心理模型，不是功能**：离线收益作为功能实现容易，本假设问的是——玩家离开后**是否愿意回来**、回来后**是否看得懂发生了什么**、看懂后**是否有事可决策**。三环缺一，放置节拍不成立。
- **MVP-0 结论的效力边界（单人口径）**：MVP-0 按单人口径收口——**数值层与机械层成立，自解释性等主观层为永久未验证敞口**（《收口记录》§3 台账 R1–R6）；量级边界文档明文「MVP-0 测试通过 ≠ 品类成立：它证明的是主动 prestige 循环成立；放置/离线的习惯循环是另一个假设，MVP-1 必须单独验证」——该边界在单人口径下只紧不松。本文不得引用 MVP-0 任何数据作为放置节拍成立的证据。
- **玩家此刻应该感到**（类比 MVP-0 §1.1）：
  1. **离开时**：我可以放心走，闭关会替我积累，且不会替我做重要决定。
  2. **回来时**：一眼看懂闭关期间发生了什么、拿到了什么。
  3. **结算后**：我有一件值得做的事（投入、突破、挑战、调整），不是「点一下就走」。
  4. **形成节奏后**：我开始预期「下次上线时会攒到 X，就能做 Y」——回访有了目标。

### 1.3 设计支柱

沿用 MVP-0 规格书 §1.3 五支柱（放置可理解 / 卡点有原因 / 调整有结果 / 归隐值得做 / 范围可实现），新增一条：

| 支柱 | MVP-1 表达方式 | 判定标准 |
|---|---|---|
| 回访有决策 | 出关结算后必然衔接至少一个真实决策点 | 玩家无「上线只点一下就走」的空会话（初案 §十四明文禁止的空会话设计） |

### 2.4 炼丹 / 秘境：默认不进，唯一例外条件

MVP-0 规格书 §11.2 原文是「MVP-0 验证通过后，才考虑 MVP-1 加入简单炼丹、基础离线收益**或**一个小型秘境」——这是**选择列表，不是打包清单**。本文裁定：

- **MVP-1 最小范围 = 基础离线收益一个系统**。头号假设只需要它即可验证；加系统违反 MVP-0 确立的「不要为未来系统提前增加复杂实现」（规格书 §11.2）与「只做必要系统」支柱。
- **唯一例外条件**：MVP-1 测试（或纸面模拟）发现**回访会话缺决策点**——即初案 §十四「每次会话必须包含至少一个决策点」无法由既有决策（资源投向、升武学、突破、挑战 Boss、调整构筑）满足时，才评审加入炼丹或小型秘境**之一**作为回访决策载体，且二选一、不同时进。
- 声望商店平台期衔接（§2.1）优先用**追加声望节点**解决，不自动升级为新系统。

## 3. 核心循环规格：回访会话

### 3.1 单次回访会话（3–10 分钟 `[待定-重推批次]`）

```text
上线 → 出关结算（离线收益入账，一屏看懂）→ 回归检查（进度/资源/卡点现状）→ 决策投入（升级/突破/挑战/调整/资源投向）→ 设定下次目标（可预期「下次回来能做什么」）→ 离线（闭关开始）
```

- **紧张感来源**：离线上限（§5）——收益封顶后继续离线是浪费，构成回访动机；但不做惩罚性机制（无「不回来就扣东西」）。
- **胜利状态**：会话内完成至少一个有意义决策，并对下次回访形成预期。
- **失败状态**：上线发现无事可做（空会话）——这是 §8.2 表的头号失败现象，不是玩家的错。

### 3.2 单日循环（2–3 次会话 `[待定-重推批次]`）

早/晚各一次回访为基准想象，节奏由离线上限与产出速率共同调节。会话间隔与离线上限的匹配关系是数值重推批次的核心命题（间隔 > 上限 = 浪费感；间隔 << 上限 = 上限形同虚设）。

### 3.3 长期循环（跨日与轮次）

MVP-0 的「归隐 → 第二轮更快」循环原样保留，叠加维度是：**轮长从单会话拉长为多会话跨日**（锚点见 §4），归隐决策从「本次会话内的终点」变为「若干天节奏后的里程碑」。prestige 循环与放置节拍在此汇合——这也是两个假设必须分开验证的原因：汇合处的任何失败都需要能归因到单独一环。

## 4. 会话结构与轮长锚点

> 本节全部数字为**讨论起点**，出自初案 §十四（其表内原生 `[待测试]` 标记原样有效）；MVP-1 实际取值一律标 `[待定-重推批次]`，由数值表重推批次定值。

### 4.1 轮长锚点

初案 §十四单轮时长曲线：第 1 轮 30–60 分钟（= MVP-0）、第 2 轮 1–2 小时、第 3–5 轮半天–2 天。MVP-1 验证放置节拍需要**轮长跨越至少一次真实离线间隔**。

**v0.2 状态：轮长与自测窗口均 `[待定-终裁]`**。所有者意向为更短窗口（1 天内完成整个自测）；设计侧裁决 1 天不可行作为假设验证，反提案 =「阶段 A 1 天功能验收 + 阶段 B 3 天正式窗口」，轮长配套「活跃 45–90 分钟/轮、日历跨度约 1 天」。两案对照、有效域论证与降级选项全文见 §10 开放问题 1；**终裁前数值表重推批次不得取数**。有效域底线（无论终裁取哪档）：回访间隔须至少覆盖一次睡眠间隔，否则心理模型退化回 MVP-0 已验证的「等资源」，重复证明旧假设。

### 4.2 重推方法论（引用，不重复造）

按量级边界文档口径执行：

- **「怎么算」保留，「算多大」不保留**——公式、规则、守则、曲线形状带进 MVP-1；具体数字、配比、时长全部按新轮长锚点重新反推（量级边界文档「一句话原则」）。
- 重推方式 = 换锚点后按各表头部的「推导锚点」重推一遍，规则层原样沿用（同文档「对后续工作的含义」第 2 条）。
- 任何新增数值/系统先过规则层四项检查：加成域归属、乘区是否超 2、资源三列账是否闭合、是否触碰门槛 Boss 守则与 ≤5 分钟节拍红线（同文档第 3 条）。
- ≤5 分钟可见进展红线是**在线尺度**约束；其在离线/回访节拍下的等价约束（回访会话内多久必须有一次可见进展）由本次验证的结论另定（`zhoutian-direction-note.md` §6 第 3 项预留的同一问题）。

## 5. 离线收益规则（方向锁定，数值待定）

| 规则 | 方向（锁定） | 数值 |
|---|---|---|
| 产出范围 | 离线只产出基础资源：内力、银两、少量阅历 | 比例 `[待定-重推批次]` |
| 决策保留 | 离线**不**自动突破、**不**自动归隐、**不**获得首通奖励、**不**触发稀有奇遇、**不**推进 Boss——所有关键决策必须留给在线时刻 | —（规则无数值） |
| 时长上限 | 有上限，收益封顶构成回访动机 | 初始 4 小时 `[待定-重推批次]`；声望天赋提升档位（8/12/24h）属完整版离线域设计，MVP-1 是否放入首档由重推批次定 |
| 离线效率 | 低于在线挂机，且任何加成后不得超过在线 100% | 60%–80% `[待定-重推批次]` |
| 加成归属 | 离线相关加成统一归属「离线域」（初案 §四加成域体系），不与既有永久/本轮乘区混淆 | —（归属规则无数值） |
| 结算时点 | 回归上线时一次性结算并呈现（出关结算）；**离线期间不做后台实时结算** | — |

> **与 MVP-0 实现的衔接注记**：MVP-0 实现路线图（规格书 §12）明文「页面关闭期间不结算任何收益」，该条款的存在目的就是防止离线收益在 MVP-0 阶段被顺手实现、污染本假设。MVP-1 开工（过门禁后）时解除该条款，解除动作本身列入实现路线图首项。

## 6. 闭关—出关结算呈现（设计要求，非实现细节）

放置节拍的头号自解释关口是**出关结算**——玩家离开 8 小时后回来的第一屏，决定「回归检查」这一环是否成立。硬性要求（类比 MVP-0 §8.6 的写法，细化归呈现层规格交付物）：

1. **一屏看懂**：闭关时长、获得资源明细、是否触顶（上限已满的明确提示）——三项信息一屏内呈现，不埋层级。
2. **数值可信**：结算数字 = 结算函数实际输出，可核对（时长 × 速率 × 效率的构成可查）——PRODUCT.md 原则 1 在离线场景的直接延伸。
3. **不越权确认**：结算屏应让玩家确认「闭关没有替我做决定」（无突破、无战斗推进），与 §5 决策保留规则互为表里。
4. **衔接决策**：结算屏关闭后直接落在一个可行动的决策入口（资源投向/突破就绪/挑战入口），30 秒内有事可做 `[待定]`——对齐「回访有决策」支柱；具体时延指标由 MVP-1 埋点规格定义。
5. **术语纪律**：玩家侧一律「闭关 / 出关结算」；「离线收益」是内部机制代号，不出现在界面文案（沿用 MVP-0 §6.1 机制与皮肤分层管理的既有做法）。

## 7. 与 MVP-0 的关系

### 7.1 规则层沿用清单（原样带入，不重推）

以下规则按量级边界文档「保留到完整版的：规则和结构」表原样沿用（出处见该表）：

1. 公式形态：双曲防御 `100/(100+DEF)`、命中率 `命中/(命中+闪避)` 下限 30%（形状保留，常数复查）。

3. 曲线形态：指数基础曲线、段内固定底数 + 段间跃迁节点、敌人曲线锚定玩家基础曲线。

5. 归隐结构：门槛锚定推关里程碑、首次后常驻、声望公式方向。
6. 设计守则：门槛 Boss 只做数值检查；≤5 分钟可见进展节拍红线（在线尺度，离线等价约束另定，见 §4.2）。
7. 经济原则：每种资源来源/主消耗/后期 sink 三列账；不没收不可再生资源。
8. **MVP-0 全部已实现系统作为基底原样保留**：5 境界 / 3 图 / 3 Boss / 三路线 / 归隐 / 8 声望节点 / 周天呈现体系——MVP-1 不改其规则，只在数值重推批次换其数字。

### 7.2 MVP-0 结论的效力边界（单人口径）

- prestige 循环成立（**单人口径**：sim 全 PASS + 所有者自测埋点，见《收口记录》§2）≠ 放置节拍成立——本文 §1.1 引用的 §1.2 原文即此边界的权威表述。
- MVP-0 **无外部测试报告**；自解释性、归隐情绪、流派认知等主观层结论一律以《收口记录》§3 敞口台账（R1–R6）为准——**未验证**，本文及一切 MVP-1 下游文档不得引用为已成立。出关结算的自解释性同属 R1，MVP-1 自测也无法自证（§8.1-2 只测数值可信 proxy）。
- 反向同理：MVP-1 自测若失败，优先归因放置节拍层（回访/结算/决策点），不自动否定已按单人口径成立的主动循环——归因隔离是两阶段拆分的全部意义。

### 7.3 自测形式（单人多日 dogfood）

- MVP-0 的 90–120 分钟陪同制方案**未执行、已存档**（《收口记录》§5-1）；MVP-1 不采用陪同制——陪同环境里不存在真实的「离开与回来」。
- MVP-1 采用**单人多日 dogfood 自测**，两阶段协议（窗口天数 `[待定-终裁]`，见 §10-1）：
  - **阶段 A（功能验收，1 天）**：出关结算数值可信链路、回访决策点结构、触顶机制行为（上限临时压低可当日多次触顶）、界面完整性。产物 = 阶段 B 放行；数据标记 shakedown 不入统计，允许修 bug。
  - **阶段 B（正式窗口，假设验证）**：自然生活嵌入的自发回访采样。窗口内数值/文案冻结（冻结纪律在此重新生效，服务前后可比）；发现的问题只记不修（双帽分离）。
- **防偏差装置**（细则与阈值由《MVP-1 自测执行方案》定稿，预登记先于阶段 B 开跑）：
  1. **预登记**：开测前把 §8 每条标准的预期值区间与失败信号阈值写死（预期值来自数值重推批次的推导，不是测后拟合）；测后只对照，不新增解释。
  2. **失败信号触发即承认**：预定义阈值触发即记该环失败，禁止「那天太忙」类事后豁免（外部原因可标注，不可移出分母——沿用 MVP-0 `design_dropout` 留分母的精神）。
  3. **自然嵌入**：无闹钟、无日程、无待办项，回访必须由「想到它」驱动。
  4. **即时笔记**：每次会话后 ≤1 句当场记录（防事后合理化）；报告中主观内容只作附注，不作判定依据。
  5. **双帽分离**：正式窗口内设计者帽与玩家帽不得同时戴——改一个数就是废一窗数据。
- 埋点前提：跨会话/跨日采集超出 MVP-0 埋点「一次性本地导出」的设计范围，按其范围纪律另立《MVP-1 埋点增补规格》（交付物 ⑤′），复用 MVP-0 事件信封格式。

## 8. MVP-1 成功与失败标准（草案）

> 本节数值目标全部 `[待定-预登记]`，定值时机 = 《MVP-1 自测执行方案》的**预登记表**（开测前基于数值表重推批次的推导写死预期值与失败阈值，测后只对照、不新增解释）。判定采**双轨口径：埋点客观指标为主、自测者行为证据为辅**——设计者无法自证的访谈类判据已删除或转敞口（《收口记录》§3）。

### 8.1 设计验证成功

若阶段 B 自测中出现以下结果，可认为放置节拍方向成立：

| # | 标准 | 客观判据（埋点，不撒谎） | 行为判据（自测者） | 转敞口部分 |
|---|---|---|---|---|
| 1 | 回访意愿 | 正式窗口内自发回访间隔分布与离线上限匹配 `[待定-预登记]` | 无日程、无提醒、无待办项条件下回访自然发生——回没回来埋点不撒谎 | 动机可泛化到非设计者（R4） |
| 2 | 出关结算可信 | 结算数字与引擎输出同源校验通过（数值可信可机器自证）；结算屏停留时长落在合理带 `[待定-预登记]` | — | **自解释性本体**：设计者无法看不懂自己的设计（R1） |
| 3 | 回访有决策 | 空会话占比 < `[待定-预登记]`；出关结算 → 首个决策事件时延 ≤ `[待定-预登记]` | — | 无 |
| 4 | 上限机制有效 | 触顶浪费率 < `[待定-预登记]`——设计者本人都频繁触顶浪费 = 上限与真实生活节奏错配的**诚实信号** | — | 「上限被理解」本体（R1/R5） |
| 5 | 节奏形成 | 正式窗口后半段回访间隔方差收敛 `[待定-预登记]`（**窗口 ≥3 天方可采样**，见 §10-1） | 即时笔记出现「预期下次上线能做 X」类当场记录 | 感知泛化（R6 同类） |
| 6 | 在线仍有价值 | 在线会话决策事件密度 ≥ `[待定-预登记]`；纯收菜会话占比 < `[待定-预登记]` | 在线会话中仍自发发生挑战/突破/调整 | 无 |

### 8.2 设计验证失败

若出现以下任一情况，应优先调整 MVP-1 放置层，而不是继续扩系统。判据来源一律为埋点与即时笔记（预登记阈值触发即承认）：

| 失败现象 | 可能原因 | 处理方向 |
|---|---|---|
| **设计者本人在正式窗口内出现任一自然日零自发回访（最强红旗）** | 回访动机崩溃——设计者对自家游戏的回访义务感是**正偏差**，连义务感都压不住的不上线无可辩驳 | 触发即承认「回访意愿」环失败，禁止事后豁免；**窗口 < 2 天时该信号不可采样**（见 §10-1） |
| 上线只点一下就走（空会话超阈值） | 回访决策点不足 | 先查既有决策（资源投向/突破/挑战）的呈现衔接（§6-4）；仍不足则触发 §2.4 唯一例外条件，评审炼丹/秘境之一 |
| 出关结算数字对不上 / 构成不可查 | 结算构成不透明或呈现层级过深 | 按 §6-1/-2 重做结算屏信息架构；数值可信是红线，不许用演出掩盖 |
| 回访间隔远超上限（触顶浪费常态化） | 回访动机不成立：上限太宽 / 收益预期太弱 / 无牵挂目标 | 收紧离线上限或强化「下次目标」呈现；即时笔记显示根本不想回来 → 按 §7.2 归因隔离核查循环层还是节拍层 |
| 回访过密（远小于上限，接近在线挂机） | 上限/速率错配，离线形同虚设 | 重推上限与产出速率匹配关系（§3.2 命题）；确认非自测义务感装置效应（§7.3 自然嵌入纪律） |
| 离线被体验为惩罚（即时笔记记录「不在线就亏」焦虑） | 效率折扣感知过重或触顶浪费感过强 | 调效率比或触顶前提示；不引入「不回来就扣东西」类机制（§3.1 底线） |
| 在线时刻失去意义（纯收菜化） | 离线效率过高或在线独占内容太薄 | 压离线效率（≤ 在线 100% 是硬规则，实际值应显著低于）；检查在线独占决策（Boss/首通/突破）的密度 |
| 回访后无进展感（会话内无可见变化） | 离线产出量不足以支撑会话内一次投入 | 重推产出/消耗配比，使单次标准离线期 ≈ 至少一次有意义投入 `[待定-预登记]` |
| 归隐节奏被离线打乱（多日轮长下归隐门槛遥不可及或秒达） | 轮长锚点与离线速率错配 | 回 §4.1 重定轮长锚点；prestige 层规则不动，只动数字 |

### 8.3 MVP-1 不用验证的指标

- 7 日/30 日留存、商业化转化（沿用 MVP-0 §10.3）。
- 主动循环的机械/数值层（已按单人口径收口，《收口记录》§2）；其主观层敞口（R1–R6）**不由 MVP-1 自测重验**——设计者自测测不出自解释性，按《收口记录》§4 补验节点处理。
- 完整版轮长曲线（中后期 1–3 天/轮）、多门派长期声望、MVP-2 内容。
- 移动端形态：PRODUCT.md 记录碎片会话「桌面浏览器优先」，移动端优先级重估属完整版（量级边界 UI 节），MVP-1 沿用桌面。

## 10. 开放问题（待所有者终裁）

### 开放问题 1：自测窗口与轮长锚点（**待终裁**，本文数字保持 `[待定-终裁]`）

**所有者意向**（2026-07-06）：整个 MVP-1 自测在 **1 天内**完成，轮长比 1–2 小时档更短。

**设计侧裁决：1 天窗口不可行作为头号假设验证**，理由：

1. 头号假设的权威表述（§1.1 引文）点名「**隔 8 小时回访**是不同心理模型」——隔夜回访是放置品类的定义性样本，1 天窗口的隔夜样本数为零；
2. 「回访意愿」（自然生活间隔中的自发回访）、「节奏形成」（间隔方差收敛，需 ≥3 天）与「整日零自发回访」最强红旗在 1 天内均**不可采样**——一个在设计上不可能失败的测试不是测试；
3. 轮长/间隔压缩的有效域底线：回访间隔若压到小时级以下、且小于一次日常生活事件（工作/外出/睡眠），心理模型退化回「盯着等资源」——那是 MVP-0 已验证的旧假设，重复证明无信息量。

**反提案（1 + 3 两阶段）**：阶段 A **1 天**功能验收（所有者要的「1 天出结果」在此成立：结算链路/决策点结构/触顶机制/界面完整性）；阶段 B **3 天**正式窗口（含 2 个隔夜），轮长配套「活跃 45–90 分钟/轮、日历跨度约 1 天」。成本说明：阶段 B 的**主动时间投入合计约 1–1.5 小时**（每日 2–3 次 × 3–10 分钟）——放置测试花的是日历时间不是精力，1 天窗口反而要求更密集的主动注意力。

**若终裁仍取 1 天（如实记录，设计侧不推荐）**：MVP-1 从「假设验证」降级为「功能交付」——只能宣布「离线收益功能成立 + 会话结构成立」，放置节拍假设整体转入敞口台账（挂 R7），与 R1–R6 同待补验；§8.1 标准 1/5 与 §8.2 首行红旗标记「不可采样」。

如果自测者（阶段 B 的所有者本人）在自己的日常生活里，愿意隔着真实的几小时乃至一夜回来看一眼闭关收成、数字对得上、且每次回来都有一件值得做的事并开始预期下一次——那么放置节拍在单人口径下成立（可泛化性挂 R4 待补验）；否则不要扩系统，先修回访这一环。
