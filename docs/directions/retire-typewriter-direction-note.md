## 1. 同批被拒的流程改动（记录在案，防止日后重提）

**「确认归隐后先回到新一轮，再通过动画引导告知声望阁解锁」——已拒绝**，直接落地声望阁是刻意设计而非偷懒，三条理由：

1. **规格依据**：§8.6-4「结算后直接打开声望节点界面……让永久变强在归隐后 30 秒内被兑现」是硬性要求；量级边界文档明文「§8.6 本就是完整版硬性要求，不是原型便宜方案」；retire-copy §5 的落地引导气泡文案已冻结；埋点 §2.5 为此专设度量指标。
2. **标准 4 风险（重置像惩罚）**：提议流程让玩家睁眼先看到境界 1、地图 1、资源全空——把「获得 → 损失确认」的峰终顺序倒置为「损失确认 → 获得」，正踩损失厌恶；现设计保证归隐后的第一个主动动作是**获得**（购买节点）。
3. **标准 5 度量风险**：二轮提速 25%–40% 的验证建立在节点效果从 `run_start` 生效（埋点 `run_start.owned_nodes`）；购买时点若后移到二轮开局之后，头几分钟无节点加成，28% 提速信号被污染，sim 对照失效。

## 2. 打字机演出的定位

- **是 retire-copy §4 既有结算演出的演出升级，不是新内容**：主模板「你的第{N}段江湖：历时 {M} 分钟，击败了 {S} 个强敌，{最远足迹}」+ 声望入账行「江湖会记得你——声望 +{total}」即打字机的全部台本。
- 与量级边界「归隐结算是唯一铺张点」相容——铺张预算本就留给这里；MVP-0 从简是「数值可信优先于演出」的阶段取舍，不是形态否定。
- 若完整版按初案节奏做逐轮拉长（中期 1–3 天/轮），单轮历程更厚，「回顾一段江湖」的演出价值随轮长上升——这是本方向真正的主场。

## 3. 锁定点（规格化时不得违反）

1. **文案逐字取 retire-copy §4**：不新增变量、不改 `{N}/{M}/{S}/{total}/{最远足迹}` 的取值口径；文案要扩充先改 retire-copy 发版（冻结纪律）。
2. **数值可信**：打字机/滚动计数的最终定格值 = 结算函数实际输出，与预览、`retire_confirmed.prestige_total` 三处同源同值（retire-copy 头部硬校验条款原样适用）。
3. **可跳过或限长**：演出必须可跳过或总时长 ≤ N 秒 `[占位]`；**实装前置 = 重核埋点 §2.5 口径**——「30 秒兑现时延」是把演出时长计入预算、还是从 `retire_confirmed.ts` 起点中豁免演出区间，二选一先定稿再实装。MVP-0 首测的真实兑现时延分布是该定稿的输入数据。
4. **不阻塞落地引导**：演出结束（或跳过）后仍自动进入声望阁并出引导气泡，§8.6-4 链路完整不变。

## 4. 尺度归属

- **MVP-0 一字不改**：归隐流程文案与呈现属测试期冻结清单（测试方案 §7），且当前演出已含总结文案，教学与度量功能齐备。
- **MVP-1 候选**：作为归隐结算的呈现升级评审，输入 = 首测的兑现时延分布与访谈中对结算演出的主观反馈。
- **完整版**：峰值演出点随内容重新分配时（量级边界 UI 节），归隐结算演出整体重设计，本方向并入其中。

## 5. 规格化前置检查（MVP-1 立项时逐项过）

1. §3 锁定点 1–4 逐条核对（文案冻结源、同源同值、可跳过/限长与 §2.5 口径定稿、引导链路完整）。
2. 是否需要新增演出行为埋点（如跳过率）——按埋点规格「回答不了服务哪条标准的事件不进清单」的纪律裁剪。
3. retire-copy 版本联动：演出实装若触碰任何玩家可见文案，先发版 retire-copy 再动工程。
4. 打字机节奏与变量渲染：长数字/长措辞（如「踏平黑风寨，走完了华山古道」）的逐字节奏是否可控，避免演出时长随文案长度失控。
