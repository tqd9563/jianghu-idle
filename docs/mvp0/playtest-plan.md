## 1. 目的与范围

- **验证对象**：规格书 §10.1 六条成功标准；同时按 §10.2 失败现象表逐项记录是否出现。
- **测试形式**：单人陪同制（1 测试者 + 1 观察员），完整两轮，约 90–120 分钟游玩 + 前后各 10 分钟（开场说明 / 测后访谈）。
- **不验证**：§10.3 列出的全部项（留存、商业化、离线节拍等）。

## 2. 样本量与判定口径

- **正式样本 n ≥ 10，建议招募 12–14 人**以备脱落（预试跑 1–2 人另计，不入任何统计）。
- **为什么 n ≥ 10**：完成率目标是 > 80%（§10.1-1）。n=5 时挂 1 人恰为 80%，正好压在阈值上无法判定；n=10 时 9/10 与 8/10 才拉得开档位，阈值才有分辨力。
- **报告方式：一律 `x/n` + 定性结论，不报百分比精度**（10 人样本报「87.5%」是伪精度）。完成率判定档位：
  - **≥ 9/10：达标**；
  - **8/10：灰区**——结合脱落原因与保底归隐占比（埋点规格 §2.1 附报项）定性判断，倾向按 §10.2 复查而非宣布通过；
  - **≤ 7/10：不达标**，进入 §10.2 处理流程。
- 其余五条标准同理按 `x/n` 报告；标准 5（提速）额外附每个测试者的四里程碑提速比原始值（埋点规格 §2.2）。
- **规格书 §10 的「>80%」不改**：它是方向目标；本节只是给它配上小样本下可执行的判定规则。

## 3. 招募与会话形式

### 3.1 招募条件（对齐 PRODUCT.md 目标玩家假设）

| 类型 | 人数 | 条件 |
|---|---|---|
| 放置/incremental 玩家 | ≥ 6 | 玩过至少一款放置类（Cookie Clicker / Melvor / 一念逍遥等任意），能描述「转生/重置」概念 |
| 轻度武侠受众（无放置经验） | 2–3 | 对武侠题材有兴趣但没玩过 prestige 类——专测「循环是否自解释」，他们的卡点原因复述（标准 2）最有含金量 |
| 补充名额 | 其余 | 任一类均可 |

- **排除**：接触过本项目任何文档/原型者。
- **标注分层**：游戏从业者（策划/数值岗）可参加但在名册中标注，分析时单列——他们的「看懂」不能代表目标玩家。
- **设备**：桌面浏览器（PRODUCT.md 口径），观察员自带机器统一环境。

### 3.2 会话流程

1. **开场（≤5 分钟，固定脚本）**：「这是一个武侠放置游戏的早期原型，请按你自己的理解玩。想到什么可以随时说出来，我会记录。我不能回答玩法问题——按你的理解来就好。大约 90–120 分钟，中途随时可以休息。」录入 tester_id，触发 `test_session_start`。
2. **游玩（90–120 分钟）**：观察员只回答**纯软件问题**（按钮无响应、页面白屏）；一切玩法/策略/界面含义问题统一回应「按你的理解来就好」，并把问题原文记入观察表——**测试者的每一个提问都是自解释性失败的一次采样**。
3. **测后访谈（10 分钟）**：按 §5 提纲执行，录音（征得同意）。
4. **收尾**：触发 `test_session_end`（选对 reason），导出埋点 JSON，支付报酬。

### 3.3 中断规则

- 允许生理性中断：观察员点「暂停」（埋点 `test_paused/resumed`），恢复后继续，时间指标自动扣除。
- 累计中断 > 15 分钟，或测试者因外部原因（临时有事）无法继续 → 标记 `external_dropout`，出完成率分母（§10 测试注口径）。
- 测试者明确表示「不想玩了」→ 标记 `design_dropout`，**留在分母**——这正是循环失败的证据，访谈改为追问放弃原因。

## 4. 预试跑（1–2 人）

- **目的**（三项，缺一不进正式测试）：
  1. 排除可用性硬阻塞（卡死、完全看不懂以致无法推进）——把纯可用性噪声消耗在预试跑里，别让它吃正式样本；
  2. 验收埋点：导出文件跑通埋点规格 §2 全部派生指标（该规格 §4 验收清单）；
  3. 演练观察记录表与访谈提纲，校准观察员的「观察/解读」分列纪律。
- **退出条件**：预试跑者在无干预下完成首次归隐，且导出数据无缺项 → 进入正式测试；若发现阻塞，修复后再补跑 1 人验证。
- **数据纪律**：预试跑一切数据不进入 §10 统计；若修复涉及玩法/数值/文案，预试跑结论一并作废重跑。

## 5. 测后访谈提纲（不引导措辞）

主观标准的判定以本节为主、埋点交叉验证为辅。**逐条对应 §10.1，问题按原文照读，禁止用括号里的引导词**：

| 对应标准 | 问题原文 | 判定 | 禁止的问法 |
|---|---|---|---|
| 标准 2（卡点归因） | 「你有没有在哪个敌人身上停下来过？说说当时发生了什么。」→ 追问：「你觉得当时为什么打不过？」 | 归因与埋点 `diag` 记录的实际失败原因方向一致 = 达标（不要求术语准确，「它防太厚我挠不动」即合格） | 「是不是因为防御/克制的原因？」（喂答案） |
| 标准 3（调整行为，补充行为数据） | 「卡住之后你做了什么？」 | 能说出自己做过的调整及理由 = 与埋点判据互证 | 「你有没有想过换路线？」 |
| 标准 4（归隐非惩罚） | 「归隐把你的进度清掉重来了。你当时是什么感受？」→ 「点归隐之前，你犹豫了吗？在想什么？」 | 表述净值为「值得/划算/想再来」= 达标；「亏了/被坑」= 不达标 | 「你觉得重置是一种惩罚吗？」（把标准原文抛给测试者） |
| 标准 5（提速感知） | 「第二轮和第一轮相比，有什么不一样的地方吗？」→ 若未提节奏，追问一次：「过程的感觉上呢？」到此为止 | **主动**提及「更快/更顺/很快就到了 XX」= 感知成立；两问后仍未提 = 不成立（即使埋点显示实际提速达标——感知不成立本身就是 §10.2「说明不清」的证据） | 「第二轮是不是明显更快？」 |
| 标准 6（流派认知） | 「你选了 X 路线。你猜另外两条玩起来什么样？」→ 「有没有哪条你觉得最强？为什么？」 | 能说出差异想象 = 流派表达清晰；若回答「都差不多吧」记入 §10.2「三流派体验差不多」 | 「你知道唐门克高防吗？」 |
| 收尾（整体理解） | 「如果向朋友一句话介绍这个游戏，你会怎么说？」＋「最想吐槽的一点是什么？」 | 一句话中含「重来会更强」类表述 = 核心循环被理解 | — |

- **时点纪律**：全部问题放在两轮结束后。游玩中途不提问（会污染第二轮行为）；归隐时刻的即时情绪靠观察表捕捉，不靠打断。
- 追问只许用「多说一点？」「当时怎么想的？」两种中性形式。

## 6. 观察记录表

每名测试者一份，观察员实时填写。核心纪律：**观察与解读分列，观察列禁止出现形容词判断**——「困惑」是解读，「在路线选择页停留 90 秒、光标在三张卡之间移动 7 次」是观察。

| 字段 | 说明 |
|---|---|
| 时刻 | 手记大致时间即可（精确时间以埋点为准） |
| 阶段 | 预置里程碑行：首次操作 / 选路线 / Boss 1 / Boss 2 首败 / 换线或强化 / 突破境界 5 / 归隐预览 / 结算演出 / 首次购点 / 二轮开局 |
| 观察 | 客观行为 + 原话引用（测试者的每个提问必录原文） |
| 解读 | 观察员的猜测，明确标记为猜测 |
| 待验证 | 由该解读产生的访谈追问（挂到 §5 收尾后补问） |

另附 §10.2 失败现象对照页：八行现象逐行勾选「出现/未出现/存疑」，测试报告直接汇总此页。

## 7. 测试期冻结纪律

- **冻结窗口**：首名正式测试者开始 → 末名正式测试者结束。
- **冻结内容**：全部数值表（公式/内容/声望经济）、失败提示 7 级诊断文案（公式表 §5）、归隐流程文案（§8.6 三栏预览/确认/结算）、声望节点名与效果描述、路线卡文案。**中途调参或改文案 = 前后样本不可比 = 新开一批测试**，没有例外。
- **bug 修复的样本判定**：修复若触碰 §10 度量路径（战斗结算、经济数值、埋点、归隐流程）→ 修复前样本作废；纯视觉/排版修复 → 样本保留并在报告中标注。
- **报告口径**：测试报告逐条给出 §10.1 的 `x/n + 定性结论`（口径见 §2），附 §10.2 现象对照汇总与每人四里程碑提速原始值；观察列与解读列在报告中同样分开呈现。
