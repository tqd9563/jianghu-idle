## 一句话原则

**MVP-0 是一个 60 分钟的压缩原型，唯一使命是验证「prestige 循环成立」这一个假设，不是完整版的等比缩小。**

判断口诀：**「怎么算」保留，「算多大」不保留**——公式、规则、守则、曲线形状带进完整版；具体数字、配比、时长全部是为 60 分钟测试反推的，进 MVP-1 时按新的轮长目标重新出一版。

## 保留到完整版的：规则和结构（骨架）

| 类别 | 内容 | 出处 |
|---|---|---|
| 公式形态 | 双曲防御 `100/(100+DEF)`；命中率 `命中/(命中+闪避)`，下限 30%。公式的**形状**保留；常数 K=100 完整版可能分段调整（调底数须同步复查 K） | 公式表 §2 / §3.1 |
| 战斗结算规则 | 固定回合制；毒无视防御且绕过护盾；反伤按「减免后、护盾吸收前」计算；六状态的结算时机与叠加规则 | 规格书 §7.1 / §7.2 |
| 曲线形态 | 指数基础曲线；段内固定底数 + 段间跃迁节点；敌人曲线锚定玩家基础曲线同源同步 | 初案 §三、公式表 §3.1 |
| 数值全局规则 | 每个最终量乘区 ≤2；同域加法合并；4 个加成域（域间不相乘）；禁止以新增乘区作为成长感手段。明文为**完整版全局规则**，非 MVP-0 专属 | 初案 §四 |
| 归隐结构 | 门槛锚定推关里程碑；首次归隐后门槛常驻不上升；声望公式方向（里程碑锚定 + 表现加成封顶 + 短轮惩罚） | 初案 §四 |
| 设计守则 | 门槛 Boss 只做数值检查，硬克制只放在可绕过的敌人身上；「相邻可见进展 ≤5 分钟」节拍红线（充能式突破是它在 MVP-0 的实现机制） | 规格书 §6.3 / §6.1 |
| 经济原则 | 每种资源必须有来源/主消耗/后期 sink 三列账；换路线类操作不没收不可再生资源（全额返还 + 摩擦费） | 初案 §二、规格书 §6.4 |

## 刻意简化、不可外推的：量级和内容

| 简化项 | MVP-0 形态 | 完整版形态 | 出处 |
|---|---|---|---|
| 所有具体数值 | 突破消耗/敌人属性/产出速率均为原型尺度，从 60 分钟锚点反推 | 按完整版轮长曲线重新反推 | 公式表各表头「推导锚点」 |
| 突破量级 | 境界 5 突破攒约 20 分钟内力 | 同名境界处于 10 境界轴中段，单次突破数小时至一天量级 | 公式表 §3.3 |
| 突破成本构成 | 只有内力单一成本（材料被刻意抽象掉） | 四层重量感：材料（突破丹）+ 前置条件（心法/江湖挑战）+ 风险仪式（心魔试炼 + 温和失败）+ 演出 | 公式表 §3.3、初案 §三 / §九 |
| 归隐门槛 | 「境界 5 + Boss 3」双条件（门槛 = 内容边缘 = 终点线） | 推关里程碑，与境界序号脱钩 | 规格书 §6.6、初案 §四 |
| 地图×境界配比 | 3 图消耗 5 境界 | 8 图映射 10 境界，首轮内容只占总量 20%–30% | 初案 §七 |
| 境界底数 | 固定 1.7，覆盖境界 1–5 | 1.7 只是第一大境界段的底数；后续段另定，段间跃迁节点承载质变 | 公式表 §3.1、初案 §三 |
| 节奏模型 | 全程在线的主动循环，无离线 | 离线/回访节拍是品类核心；属独立假设，归 MVP-1 单独验证，MVP-0 结论不构成其证据 | 规格书 §1.2 / §10.3 |
| 毒的穿防形态 | 完全无视防御 | 「部分穿透防御」为完整版预留形态 | 规格书 §5.4 |
| 内容系统 | 无装备、无炼丹、无门派、无秘境；声望节点仅 6–10 个、首轮只买 1–2 个 | 全量系统 | 规格书 §2.3 |

## UI/呈现层的保留 vs 简化

数值层口诀在呈现层的延伸：**「怎么呈现」保留，「呈现多少」不保留**——信息架构的语法、峰终流程的形态、数值透明的表达方式带进完整版；具体的页面数量、信息密度、演出量级全部是为 60 分钟陪同测试反推的，完整版按新的系统量级与会话结构重新设计。**完整版前端原型不承诺与 MVP-0 原型同构**。

### 保留到完整版的：呈现语法（骨架）

| 类别 | 内容 | 出处 |
|---|---|---|
| 信息架构语法 | 决策面板与战斗观察分离的布局重心；「页签分层 + 常驻进度/状态条」的骨架语法（切走页签仍能看到关键进度）——页签的**数量与分组**不保留，见下表 | PRODUCT.md 原则 3/4、原型场景 3 |
| 突破的可视形态 | 分段可见进展 + 末段手动点击的仪式结构（≤5 分钟节拍红线的呈现载体）。**呈现皮肤（「充能/注入」等术语与进度条样式）可换**，分段 + 手动触发的形态保留 | 规格书 §6.1、公式表 §3.3 |
| 归隐四步流程 | 三栏损益预览 → 二次确认 → 结算演出 → 30 秒内落地引导。§8.6 本就是完整版硬性要求，不是原型便宜方案 | 规格书 §8.6 |
| 失败诊断弹窗形态 | 主提示 + 至多一条次优先的双条结构；「失败是反馈不是惩罚」的呈现姿态 | 规格书 §7.5、公式表 §5 |
| 数值透明表达 | 乘区透视、加成来源明细可核对——这是品牌立场（PRODUCT.md 原则 1），不是测试便利；完整版改变的是**默认展开程度**，不是可查性 | PRODUCT.md 原则 1 |
| 视觉 token | 夜色江湖方向（色彩/字体/间距/圆角，经 DESIGN.md 固化）。token 值可迭代，但带实现惯性，改动走 DESIGN.md 重刷流程而非随手调 | DESIGN.md（原型批准后固化） |

### 刻意简化、不可外推的：密度和量级

| 简化项 | MVP-0 形态 | 完整版形态 | 出处 |
|---|---|---|---|
| 数值裸露密度 | 全裸露——测试者（含设计者本人）需要核对每个数的来源与去向 | 透明 = 可查而非全摊：默认界面收敛，明细进 tooltip/详情层 | PRODUCT.md（Users 节点名 MVP-0 用户特殊性） |
| 导航结构 | 四页签（修炼/战斗/武学/声望阁）是 3 图 5 境界 8 节点量级的产物 | 门派/炼丹/秘境/弟子等系统进场后信息架构整体重新设计，页签数量与分组不外推 | 原型场景 3、规格书 §2.3 |
| 演出量级 | 突破演出刻意轻（数值可信优先于演出）；归隐结算是唯一铺张点 | 突破四层重量感（材料/前置/心魔试炼/演出）是**全新界面**而非现有弹层加料；峰值演出点随内容重新分配 | 公式表 §3.3、初案 §三/§九、PRODUCT.md 原则 2 |
| 视图集合 | 无离线结算、无回访视图（主动循环） | 离线结算/回归检查视图是 MVP-1 的**新增**界面，不是现有界面的改造 | 规格书 §1.2、初案 §十四 |
| 设备形态 | 桌面浏览器单布局（陪同测试环境便利） | 按碎片会话结构（单日 2–3 次、每次 3–10 分钟）重估移动端优先级 | PRODUCT.md Users、初案 §十四 |

### 原型审批标准的语义

MVP-0 原型的「已获批」**不等于**完整版视觉终稿拍板。审批标准是：**足以支撑测试，且不误导测试**。需要确定性拍板的只有三类：

1. **测试度量项**：失败诊断文案、归隐流程呈现、自解释性结构——它们本身是被测对象的一部分，测试期冻结，中途修改 = 样本作废（见《测试执行方案》§7）。
2. **DESIGN.md token**：工具固化后进入实现，带惯性，改动成本是全局重刷而非局部调整。
3. **明显错误**：对比度不达标、状态无非颜色区分等 PRODUCT.md 无障碍红线。

其余呈现细节（具体措辞、图标、面板排布微调）保持「可改」心态；完整版立项时以本节双表为界重新评审，不背 MVP-0 原型的历史包袱。

## 对后续工作的含义

1. **MVP-0 测试通过 ≠ 品类成立**：它证明的是主动 prestige 循环成立；放置/离线的习惯循环是另一个假设，MVP-1 必须单独验证。
2. **进 MVP-1 的数值工作方式**：不修改 MVP-0 各表的数字去「放大」，而是换锚点（新的轮长目标）后按各表头部的「推导锚点」重推一遍；规则层（上表第一部分）原样沿用。
3. **任何新增数值/系统先过规则层**：归属哪个加成域、乘区是否超 2、资源三列账是否闭合、是否触碰门槛 Boss 守则与 ≤5 分钟节拍红线。
4. **前端实现对 MVP-0 原型 1:1 还原，但不向完整版承诺同构**：实现阶段照原型与 DESIGN.md 执行（R2 门禁）；完整版前端原型立项时以「UI/呈现层」节的双表为界重新设计，呈现语法沿用、密度量级重推。
