## 1. 推导锚点

本文继承 `spec.md` v0.3 的裁决：MVP-1 当期只交付离线功能，不验证放置节拍假设；MVP-0 的 60 分钟压缩锚点不动，全量换锚点重推后置。

| 锚点 | 本表处理 |
|---|---|
| 不破坏 MVP-0 主循环 | 离线只发基础资源，不推进关卡 / Boss / 归隐 / 突破 / 首通。 |
| 单次满额离线收益 ≈ 一次会话级投入 | 首发表把满额收益压在「一次武学升级或一段周天充能」量级，显著小于一轮总需求。 |
| 当期可验收 | 离线上限取压缩锚点可测值，并提供调试覆盖值，支撑 §8.1 A1–A7 单日验收。 |
| 资源三列账闭合 | 离线只作为内力 / 银两 / 阅历的新增来源列；不新增付费乘区，不接商业化倍率。 |
| 玩家侧术语纪律 | 机制内部称「离线收益」；界面文案使用「闭关 / 出关结算」，不直接出现「离线收益」。 |

## 2. 结算规则

### 2.1 主公式

```text
有效闭关分钟 = clamp(原始离线分钟, 0, 离线上限分钟)

基础资源收益 = 当前最大可挂机关卡所属档位的每分钟产出
  × 有效闭关分钟
  × 离线效率
  × 追赶倍率

最终发放 = floor(基础资源收益)
```

### 2.2 驱动字段

主驱动为「当前最大可挂机关卡」，不是玩家等级。

```text
current_max_idle_stage = 玩家当前已解锁、且系统允许作为挂机收益来源的最高关卡
```

首发实现可直接使用当前主线最高可重复收益关卡作为该值；若未来出现「已通关但不可挂机」或「推荐挂机点」系统，再把该字段改为显式存档字段。

### 2.3 离线期间绝不自动执行

以下规则来自 `spec.md` §5 / §8.1-A2，本文仅落数值表口径：

- 不自动突破：丹田内力达到突破消耗时，只点亮按钮，不自动扣款。
- 不自动归隐：保底触发器不计离线时长。
- 不获得首通奖励。
- 不推进 Boss / 关卡。
- 不触发稀有奇遇。
- 不运行在线自动连战。

## 6. 追赶倍率口径

首发不启用追赶倍率，表 A 中 `catchup_per_stage = 0`、`catchup_max = 0`。

保留字段的原因：回归检查界面已经需要「追赶 / 上限 / 效率」信息槽位；未来内容量扩充后若进入自然游玩期，可不改表结构直接开启。

未来启用公式预留：

```text
进度差 = 推荐挂机进度 - 当前最大可挂机关卡
追赶倍率 = 1 + min(进度差 × catchup_per_stage, catchup_max)
```

未来启用限制：

- 只作用于内力 / 阅历，不作用于稀有掉落。
- 首次启用上限不得超过 +30%，需重新跑预算红线。
- 若启用追赶，出关结算必须展示构成：基础收益、效率、追赶加成、上限截断。

## 10. 首轮调参优先级

如果实现后体验不符合预期，按以下顺序调：

1. **先调 `offline_cap_min`**：决定回访触顶压力与单次爆发量。
2. **再调 `offline_efficiency`**：统一缩放收益，不改变各阶段相对结构。
3. **最后调三资源每分钟产出**：用于修正具体资源短缺或过剩。

不要在首轮引入商业化倍率、稀有掉落或追赶倍率来修正基础手感；这些会扩大归因面，违反 MVP-1「功能正确性交付」的当期目标。
