## 1. MVP-1 设计目标

### 1.1 头号假设：放置节拍（定义保留，验证后置）

放置节拍假设的定义如下，MVP-1 交付其功能载体：

```text
离线收益 → 回归检查 → 决策投入
```

> **v0.3 验证状态（§10-1 终裁）**：MVP-1 当期**不验证**该假设，只交付其功能载体并做功能验收（§8.1）；假设验证后置到「**内容量扩充后的自然游玩期**」（所有者原话：「具体的放置节拍可以等后续内容量充分后，自然而然的就会测试出来了」），挂账《收口记录》R7。MVP-1 当期核心目标改为：**基础离线收益的功能正确性交付**——结算对、不越权、不破坏 MVP-0 既有系统。

**文档依据**：MVP-0 规格书 §1.2 特别声明原文——

> 「放置节拍是尚未验证的第二核心假设：MVP-0 是一个 30–60 分钟的**主动**循环验证，完全不包含离线收益与回访节奏。『离线收益 → 回归检查 → 决策投入』的放置节拍是独立假设，MVP-0 通过**不构成**该假设成立的证据（**等 2 分钟资源与隔 8 小时回访是两种不同的心理模型**），该假设由 MVP-1 的基础离线收益单独验证。」

同口径见 MVP-0 规格书 §10.3（放置/离线节拍列为「MVP-0 不用验证的指标」）与量级边界文档「节奏模型」行（「离线/回访节拍是品类核心；属独立假设，归 MVP-1 单独验证」）。

### 1.2 假设边界（防止验证目标漂移）

- **验证的是心理模型，不是功能**：离线收益作为功能实现容易，本假设问的是——玩家离开后**是否愿意回来**、回来后**是否看得懂发生了什么**、看懂后**是否有事可决策**。三环缺一，放置节拍不成立。
- **MVP-0 结论的效力边界（单人口径）**：MVP-0 按单人口径收口——**数值层与机械层成立，自解释性等主观层为永久未验证敞口**（《收口记录》§3 台账 R1–R6）；量级边界文档明文「MVP-0 测试通过 ≠ 品类成立：它证明的是主动 prestige 循环成立；放置/离线的习惯循环是另一个假设，MVP-1 必须单独验证」——该边界在单人口径下只紧不松。本文不得引用 MVP-0 任何数据作为放置节拍成立的证据。
- **玩家此刻应该感到**（类比 MVP-0 §1.1）：
  1. **离开时**：我可以放心走，闭关会替我积累，且不会替我做重要决定。
  2. **回来时**：一眼看懂闭关期间发生了什么、拿到了什么。
  3. **结算后**：我有一件值得做的事（投入、突破、挑战、调整），不是「点一下就走」。
  4. **形成节奏后**：我开始预期「下次上线时会攒到 X，就能做 Y」——回访有了目标。

### 1.3 设计支柱

沿用 MVP-0 规格书 §1.3 五支柱（放置可理解 / 卡点有原因 / 调整有结果 / 归隐值得做 / 范围可实现），新增一条：

| 支柱 | MVP-1 表达方式 | 判定标准 |
|---|---|---|
| 回访有决策 | 出关结算后必然衔接至少一个真实决策点 | 玩家无「上线只点一下就走」的空会话（初案 §十四明文禁止的空会话设计） |

### 2.4 炼丹 / 秘境：默认不进，唯一例外条件

MVP-0 规格书 §11.2 原文是「MVP-0 验证通过后，才考虑 MVP-1 加入简单炼丹、基础离线收益**或**一个小型秘境」——这是**选择列表，不是打包清单**。本文裁定：

- **MVP-1 最小范围 = 基础离线收益一个系统**。头号假设只需要它即可验证；加系统违反 MVP-0 确立的「不要为未来系统提前增加复杂实现」（规格书 §11.2）与「只做必要系统」支柱。
- **唯一例外条件**：后置节拍验证（或纸面模拟 / 日常游玩观察）发现**回访会话缺决策点**——即初案 §十四「每次会话必须包含至少一个决策点」无法由既有决策（资源投向、升武学、突破、挑战 Boss、调整构筑）满足时，才评审加入炼丹或小型秘境**之一**作为回访决策载体，且二选一、不同时进。v0.3 注：该评审时点随节拍验证一并后置（§10-3）。
- 声望商店平台期衔接（§2.1）优先用**追加声望节点**解决，不自动升级为新系统。

## 3. 核心循环规格：回访会话

### 3.1 单次回访会话（3–10 分钟，设计意图值；当期不设验证目标）

```text
上线 → 出关结算（离线收益入账，一屏看懂）→ 回归检查（进度/资源/卡点现状）→ 决策投入（升级/突破/挑战/调整/资源投向）→ 设定下次目标（可预期「下次回来能做什么」）→ 离线（闭关开始）
```

- **紧张感来源**：离线上限（§5）——收益封顶后继续离线是浪费，构成回访动机；但不做惩罚性机制（无「不回来就扣东西」）。
- **胜利状态**：会话内完成至少一个有意义决策，并对下次回访形成预期。
- **失败状态**：上线发现无事可做（空会话）——这是 §8.3 失败表的头号现象（后置验证启用时判定）；当期由 §8.1-A2/A5 验收其结构正确性。

### 3.2 单日循环（2–3 次会话，设计意图值；当期不设验证目标）

早/晚各一次回访为基准想象，节奏由离线上限与产出速率共同调节。会话间隔与离线上限的匹配关系是**离线数值增补表**的核心命题（间隔 > 上限 = 浪费感；间隔 << 上限 = 上限形同虚设）——当期按压缩锚点的预算约束取值（§4.1），后置节拍验证时按真实生活间隔重估。

### 3.3 长期循环（跨日与轮次）

MVP-0 的「归隐 → 第二轮更快」循环原样保留。**「轮长从单会话拉长为多会话跨日」随全量重推批次后置**（§4.1）——当期轮长维持 MVP-0 压缩锚点，离线只是轮内资源积累的并行通道，不改变轮次结构。prestige 循环与放置节拍的汇合命题（任何失败须能归因到单独一环）在后置验证批次生效。

## 4. 轮长锚点与当期数值工作范围

### 4.1 轮长锚点裁决（v0.3 定稿）：保留 MVP-0 压缩锚点不动

**裁决：MVP-1 保留 MVP-0 的 60 分钟压缩锚点，全部既有数值表一字不改；当期数值工作缩减为一张「离线数值增补表」**（上限 / 效率 / 产出比，挂现有经济表体系）。**全量换锚点重推推迟到「内容量扩充批次」**，与后置的节拍验证同行。

理由：

1. **轮长重推的唯一当期目的已消失**：重推是为了让轮长跨越真实离线间隔以服务节拍验证（v0.2 §4.1 的全部论证都为此服务）；§10-1 终裁将验证后置，重推失去当期目的——为不验证的东西重推全表是纯成本。
2. **功能验收在压缩锚点上完全可执行**：离线上限临时压低即可当日多次覆盖触顶用例（§8.1-A4），结算链路正确性与锚点尺度无关。
3. **改动面最小**：锚点不动 = sim golden 对照零迁移、Boss 需求矩阵零迁移、声望经济三轮收支零迁移——MVP-0 回归验收（§8.1-A7）的基线保持干净。

**连带后果（周天动态 N）**：v0.2「撞线即进」的前提是轮长重推导致突破消耗膨胀；锚点不动则 MVP-0 实测最长充能段 4.0 分钟 < 5 分钟红线继续成立，**撞线前提失效**，动态 N 随全量重推批次后置（§2.2 已更新）。

**新增当期命题——离线预算约束**：压缩锚点下离线收益的相对威力极大（境界 5 突破 ≈ 20 分钟在线内力；若按初案完整版起点值「上限 4h × 效率 60–80%」，一夜离线 ≈ 数轮资源，玩家隔天上线即可跳过整轮的「卡点 → 调整」张力）。因此增补表必须按以下预算线取值：

```text
单次满额离线收益 ≈ 一次会话级投入（一次武学升级或一段周天充能），
且 << 一轮总需求 —— 具体比值 [待定-增补表]
```

这意味着当期上限/效率大概率**显著低于**初案的 4h / 60–80%（那是完整版轮长下的起点值）；初案原生数字在本文 §5 保留为方向记录，取值以增补表为准。

### 4.2 重推方法论（保留给后置批次引用，当期不执行）

以下口径适用于**内容量扩充批次**的全量重推，按量级边界文档执行；当期唯一适用项是第 3 条（增补表的新增数值须过规则层检查）：

- **「怎么算」保留，「算多大」不保留**——公式、规则、守则、曲线形状带进新批次；具体数字、配比、时长按新轮长锚点重新反推（量级边界文档「一句话原则」）。
- 重推方式 = 换锚点后按各表头部的「推导锚点」重推一遍，规则层原样沿用（同文档「对后续工作的含义」第 2 条）。
- **任何新增数值/系统先过规则层四项检查**：加成域归属、乘区是否超 2、资源三列账是否闭合、是否触碰门槛 Boss 守则与 ≤5 分钟节拍红线（同文档第 3 条）——**离线数值增补表当期即适用本条**（离线加成归离线域、离线产出入内力/银两/阅历三列账的「来源」列）。
- ≤5 分钟可见进展红线是**在线尺度**约束；其在离线/回访节拍下的等价约束由后置节拍验证的结论另定（`zhoutian-direction-note.md` §6 第 3 项预留的同一问题）。

## 6. 闭关—出关结算呈现（设计要求，非实现细节）

放置节拍的头号自解释关口是**出关结算**——玩家离开 8 小时后回来的第一屏，决定「回归检查」这一环是否成立。硬性要求（类比 MVP-0 §8.6 的写法，细化归呈现层规格交付物）：

1. **一屏看懂**：闭关时长、获得资源明细、是否触顶（上限已满的明确提示）——三项信息一屏内呈现，不埋层级。
2. **数值可信**：结算数字 = 结算函数实际输出，可核对（时长 × 速率 × 效率的构成可查）——PRODUCT.md 原则 1 在离线场景的直接延伸。
3. **不越权确认**：结算屏应让玩家确认「闭关没有替我做决定」（无突破、无战斗推进），与 §5 决策保留规则互为表里。
4. **衔接决策**：结算屏关闭后直接落在一个可行动的决策入口（资源投向/突破就绪/挑战入口），30 秒内有事可做 `[待定]`——对齐「回访有决策」支柱；具体时延指标由 MVP-1 埋点规格定义。
5. **术语纪律**：玩家侧一律「闭关 / 出关结算」；「离线收益」是内部机制代号，不出现在界面文案（沿用 MVP-0 §6.1 机制与皮肤分层管理的既有做法）。

> **呈现裁决（所有者，2026-07-07，原型场景 11 审阅意见落地）**：
> ① **合并一屏**——出关结算与回归检查不拆两屏，合并为单屏账目式呈现（结算三资源 + 触顶提示 + 不越权确认 + 回归检查现状），本条细化 §6-1；
> ② **构成公式仅测试通道显示**——三因子构成明细（时长 × 速率 × 效率）挂观察员/调试通道（`#observer=1`）显示，玩家侧默认隐藏；§6-2「可核对」红线由观察员通道满足（当期唯一玩家即所有者本人，通道即玩家侧可查），公开分发时是否向玩家开放随 R1 补验批次重估；
> ③ **关闭落点 = 回归主界面**——结算屏经单一按钮（文案取「出关 · 回归江湖」方向，冻结件随 ④″ 定稿）回主界面，§6-4 的决策衔接由回归检查块内的现状信息（突破就绪/卡点）+ 主界面既有决策入口承接；
> ④ **数值入账动效**——有效闭关分钟与三资源自零滚动至实发值（烛火微光呼吸，约 1 秒，`prefers-reduced-motion` 降级为直接显示）；动效只做入账反馈，不得违反 PRODUCT.md 反参考（无弹字、无频闪）。

| 6 | 在线仍有价值 | 在线会话决策事件密度 ≥ `[待定-预登记]`；纯收菜会话占比 < `[待定-预登记]` | 在线会话中仍自发发生挑战/突破/调整 | 无 |

### 8.3 节拍验证失败现象表（**后置验证启用时生效**，当期不判定）

若后置验证中出现以下任一情况，应优先调整放置层，而不是继续扩系统。判据来源一律为埋点与即时笔记（预登记阈值触发即承认）：

| 失败现象 | 可能原因 | 处理方向 |
|---|---|---|
| **设计者本人在正式窗口内出现任一自然日零自发回访（最强红旗；后置验证启用时生效）** | 回访动机崩溃——设计者对自家游戏的回访义务感是**正偏差**，连义务感都压不住的不上线无可辩驳 | 触发即承认「回访意愿」环失败，禁止事后豁免；窗口 < 2 天时该信号不可采样 |
| 上线只点一下就走（空会话超阈值） | 回访决策点不足 | 先查既有决策（资源投向/突破/挑战）的呈现衔接（§6-4）；仍不足则触发 §2.4 唯一例外条件，评审炼丹/秘境之一 |
| 出关结算数字对不上 / 构成不可查 | 结算构成不透明或呈现层级过深 | 按 §6-1/-2 重做结算屏信息架构；数值可信是红线，不许用演出掩盖 |
| 回访间隔远超上限（触顶浪费常态化） | 回访动机不成立：上限太宽 / 收益预期太弱 / 无牵挂目标 | 收紧离线上限或强化「下次目标」呈现；即时笔记显示根本不想回来 → 按 §7.2 归因隔离核查循环层还是节拍层 |
| 回访过密（远小于上限，接近在线挂机） | 上限/速率错配，离线形同虚设 | 重推上限与产出速率匹配关系（§3.2 命题）；确认非自测义务感装置效应（§7.3 自然嵌入纪律） |
| 离线被体验为惩罚（即时笔记记录「不在线就亏」焦虑） | 效率折扣感知过重或触顶浪费感过强 | 调效率比或触顶前提示；不引入「不回来就扣东西」类机制（§3.1 底线） |
| 在线时刻失去意义（纯收菜化） | 离线效率过高或在线独占内容太薄 | 压离线效率（≤ 在线 100% 是硬规则，实际值应显著低于）；检查在线独占决策（Boss/首通/突破）的密度 |
| 回访后无进展感（会话内无可见变化） | 离线产出量不足以支撑会话内一次投入 | 重推产出/消耗配比，使单次标准离线期 ≈ 至少一次有意义投入 `[待定-预登记]` |
| 归隐节奏被离线打乱（多日轮长下归隐门槛遥不可及或秒达） | 轮长锚点与离线速率错配 | 回 §4.1 重定轮长锚点；prestige 层规则不动，只动数字 |

> **当期例外**：上表第 7 行「归隐节奏被离线打乱」的**数值前置**（离线收益不得跳过轮内张力）当期即由 §4.1 预算约束 + §8.1-A1/A4 守住——这是唯一一条不等后置验证、在增补表阶段就要防住的失败现象。

## 11. MVP-1 一句话验收标准

**当期（功能交付）**：如果闭关结算的每一个数字都对得上账、离线期间没有替玩家做任何决定、触顶与关页刷新的每条边界都行为正确、且 MVP-0 的一切照旧——那么 MVP-1 功能交付成立（§8.1 A1–A7 全过）。

**后置（节拍验证，R7 销账条件）**：如果在内容量充分后的自然游玩期里，所有者按 §7.3 后置协议采样，愿意隔着真实的几小时乃至一夜回来、数字可信、每次回来都有一件值得做的事并开始预期下一次——那么放置节拍在单人口径下成立（可泛化性仍挂 R4）；否则不要扩系统，先修回访这一环。
