## 1. 映射口径

| 概念 | 定义 |
|---|---|
| 有意义投入 | 境界 / 周天推进、一次武学升级、调整余量中的任意一项。 |
| 完整卡点准备 | 从上一个主线 Boss 标准配置到当前 Boss 标准配置所需的境界增量 + 武学增量 + 调整余量。 |
| 剩余跑轮需求 | 从当前标准准备状态到标准归隐仍需完成的全部投资。 |

三资源保持独立向量，禁止把内力、银两、阅历相加成单一总成本。阅历重配按流动性记录；100% 返还部分不是净消耗。

## 3. 所有者政策校准敏感性

该敏感性不再使用 MVP-0 `neili/s × 3600`。基础小时率以 50% 档在 4h 恰好覆盖 lv10 武学成本为所有者政策校准，效率只应用一次：

```text
base_hourly_neili = lv10_cost / 4h / calibration_efficiency
                  = 4132 / 4 / 0.50
                  = 2066
earned_neili = floor(base_hourly_neili × min(absence_hours, 8) × efficiency)
```

`2066` 是校准基础率；50% 通过 lv10 武学锚点是构造结果，不是独立证据或预选档。35% / 65% 仅是围绕该锚点的敏感性。该表仅核对跨卡点武学成本，不构成 Boss 2–5 完整资格判断。结算向下取整且封顶 8h；银两 / 阅历小时率为 0。

归一化敏感性得到的约 `5.50h` 只是 50% 候选的审计参照，不是要求正式成本硬凑该值；真实产出曲线不支持时，应重审效率而非抬高成本。

## 5. Day 1 / Day 3 证据边界

Day 1 / Day 3 是预测里程碑，不是实测。唯一场景输入为 `sim/attainment-input-v1.json`：Day1 累计主动 3h、累计 1 个封顶 8h 离线块；Day3 累计主动 10.5h、累计 2 个离线块，因此 Day1→Day3 新增 7.5h 主动与 1 个 8h 离线块。主动率独立于 MVP-0 秒率，按 50% Day1 恰达构造：`(50,952−7,134−8,264)÷3=35,554÷3=11,851.333… 内力/h`。这是所有者政策构造预测，不是独立生产证据；输出保持 `evidence_forecast`，生产最终定档前仍须自然窗口实测。

时间线事件为不可变类型，来源 ID 唯一；主动、离线、首通、支出、Boss 前快照、Boss 奖励分型。三资源分别对账；Boss 4/5 奖励未获授权，输入中显式记三资源均为 0，且事件仍位于各自 Boss 前快照之后。三路线资源相同但仍分别输出并显式比较相等。

支出只有余额足够时才应用；35% 在 Day1 无法承担 Boss4 完整准备，因此不扣成负数，后续 Boss5 快照标记 unavailable，Day3 门禁为 false。8h 安全门禁只比较对应 Boss 的完整准备，不声称整轮防坍缩；remaining-run threshold 尚未授权。

## 6. 当地资源来源曲线（Boss 2 / Boss 3）

§3 要求银两/阅历由事件来源模型替代伪造连续小时率。本节落地：闲置曲线只建模内力连续产出率，事件曲线只建模里程碑/首通奖励累计。二者各自独立——闲置率不计入事件累计，事件累计不含闲置产出。

### 6.1 字段定义

| 字段 | 类型 | 说明 |
|---|---|---|
| `IdleCurve.realm` | int | 闲置产出境界（Boss 前标准配置境界）。 |
| `IdleCurve.neili_per_second` | Decimal | `9 × 1.25^(realm−1)` neili/s，出处 `content.md` §1。 |
| `IdleCurve.neili_per_hour` | Decimal | `neili_per_second × 3600`。 |
| `EventCurve.map_id` | int | 所属地图编号。 |
| `EventCurve.stage_range` | tuple[int, int] | 事件覆盖的关卡区间（不含 Boss 关）。 |
| `EventCurve.segments` | tuple[EventSegment, ...] | 按来源类别（普通/精英）切分的连续段。 |
| `EventSegment.category` | str | `"normal"` 或 `"elite"`，仅作溯源标签。 |
| `EventSegment.per_stage` | StageReward | 该段每关首通奖励（内力/银两/阅历）。 |
| `EventSegment.cumulative` | StageReward（派生） | `per_stage × stage_count`。 |
| `EventCurve.cumulative` | StageReward（派生） | 全段累计，机械推导。 |
| `local_idle_hours` | Decimal | `full_preparation_neili / neili_per_hour`，仅内力单一资源比较。 |

### 6.2 首发值

| 卡点 | 闲置境界 | 闲置 neili/s | 闲置 neili/h | 事件内力 | 事件银两 | 事件阅历 | 闲置小时(仅内力) |
|---|---:|---:|---:|---:|---:|---:|---:|
| Boss 2 | 3 | 14.0625 | 50,625 | 1,650 | 220 | 55 | ≈0.227 |
| Boss 3 | 4 | 17.578125 | 63,281.25 | 3,300 | 360 | 93 | ≈0.365 |

- 闲置率：`../mvp0/content.md` §1（9×1.25^(境界−1)/秒）。
- 事件累计：`../mvp0/content.md` §2 地图 2/3 stages 1–9（Boss @stage 10 排除）。
- 段切分：每次来源类别切换（普通→精英或反向）为一段——Boss 2 为 5 段，Boss 3 为 7 段。
- 闲置小时不涵盖银两/阅历就绪（事件/流动性门控），不构成完整就绪判定。

### 6.3 事件总收入 vs 完整准备成本

| 卡点 | 事件内力 | 完整准备内力 | 覆盖比 | 事件银两 | 调整银两 | 覆盖比 |
|---|---:|---:|---:|---:|---:|---:|
| Boss 2 | 1,650 | 11,506 | 14.3% | 220 | 200 | 110% |
| Boss 3 | 3,300 | 23,108 | 14.3% | 360 | 200 | 180% |

事件内力仅覆盖约 14% 的完整准备内力——闲置产出是主引擎，事件奖励为辅。事件银两超过调整银两需求，但银两/阅历为事件/流动性门控，不构成完整就绪。

## 7. 卡点库存快照与部分门禁

`sim/checkpoint_snapshot.py` 通过 MVP-0 模拟器的 opt-in sink，在 Boss 2 / Boss 3 首次挑战前记录钱包、境界/武学/节点、已完成关卡索引及累计收入/支出。默认模拟输出与决策不变。

- Boss 2：三路线快照一致（r3/l4/n1，stage index 17）。
- Boss 3：华山/少林一致（r4/l6/n2），唐门为 r5/l8/n2；因此真实评估保留 3 个独立库存形态，不强行合并。
- 首通事件奖励已包含在累计收入、当前钱包或节点支出中；真实离线评估不再次加算。
- Owner 裁决：每个卡点的 200 银两调整余量为可选、非累计；它只作为独立诊断，核验当前银两能否承担一次 200 调整及可返还阅历流动性，不进入完整准备或有意义投入主门禁，也不要求 Boss 2 + Boss 3 合计 400。

状态差额由冻结境界成本与 `skill_cost(level)` 逐级求和：

| 快照 → 目标 | 境界差额 | 武学差额 | 准备内力 | 至 r5/l8 剩余内力 |
|---|---:|---:|---:|---:|
| Boss 2 r3/l4 → r4/l7 | 10,000 | lv5–7 = 768 + 1,076 + 1,506 | 13,350 | 36,458 |
| Boss 3 华山/少林 r4/l6 → r5/l8 | 21,000 | lv7–8 = 1,506 + 2,108 | 24,614 | 0 |
| Boss 3 唐门 r5/l8 → r5/l8 | 0 | 0 | 0 | 0 |

离线率同样跟随快照境界：Boss 2 r3 为 `50,625/h`，Boss 3 华山/少林 r4 为 `63,281.25/h`，Boss 3 唐门 r5 为 `79,101.5625/h`；不改写 `real_mapping.py` 的标准基线常量。

首轮 3 个库存形态 × 3 档效率 × 3 档时长，共 27 条真实场景：连续离线产出仅内力（Boss 2 `50,625/h`、Boss 3 `63,281.25/h`），银两/阅历离线新增恒为 0。

| 部分门禁 | 结果 |
|---|---|
| 4h 至少一项有意义投入 | 9/9 |
| 8h 完整卡点准备 | 9/9 |
| 4h 可选调整流动性可用（诊断） | 9/9 |
| Boss 2 8h 剩余跑轮压缩风险存在 | 3/3 |
| Boss 3 8h 剩余跑轮压缩风险 | N/A（仍需在线击败 Boss 3 + 归隐） |
| Boss 4 / Boss 5 | blocked（§4 输入未定） |

以上只报告部分门禁，不选择效率档。第二轮/后续轮倍率与合成 sensitivity 均不进入真实报告。
