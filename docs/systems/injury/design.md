## §0 这套系统在做什么

现在的战斗是「无记忆」的：每一场都满血重开，打完不留痕。受伤系统给角色加上一层**跨战斗的身体状态**——一场硬仗打崩了，你会带着内伤或外伤走出战场，之后一段时间都更弱，直到养好。

它有两个作用：

- **给战斗添风险层**：赢不再是唯一结果。硬撑一场没把握的仗，可能惨胜带伤，让接下来的路更难走。
- **喂给转世系统的「战死」**：伤势重到极致会折损寿元，甚至当场不治、被迫转世（见 `reincarnation/design.md` §2.2）。受伤因此不只是掉属性，重起来会要命。

**一条实现红线**：战斗核心公式 `fight()` 和金标准 sim（`mvp0_sim.py`）逐行对齐、golden 测试逐数校验，**不许动**。受伤走一条现成的安全通道——像残页效果那样（`applyFragmentEffectsToBuild`），**在战斗开始前把伤势的影响叠加到玩家 Build 上**，`fight()` 内部完全不变。

## §1 伤从哪来：只在硬仗上

普通杂兵战一局要打成百上千场，如果每场都可能受伤，玩家会淹没在伤势管理里，挂机体验就毁了。所以受伤**只在硬仗上产生**：

- 败给 **Boss 或精英**；
- 关键战**惨胜**（低血通关）。

普通关卡的战斗不产生任何伤势。这样受伤天然稀疏、每一次都有分量——它是一个信号：**你正在触碰自己能力的边界**。

> **预留扩展**：日后可加「特定敌人机制施加」——比如中了毒敌人的招留下毒伤、被破甲敌人打出外伤。首发不做，但伤型表（§3）为它留好了位置。

## §2 伤怎么好：挂机自然养，也能花钱加速

### §2.1 时间自动疗愈（主）

伤势随游戏内时间**自动减轻**，不需要任何操作。这最贴放置游戏的本质——挂机就是养伤，静养就是疗伤。它和转世系统共用同一套「游戏内时间」时钟，不新造机制。

**离线也养伤**：和年岁的走法一致，离线期间按结算时长恢复、同样有封顶。而且离线不打仗、不会受新伤，所以**下线休息 = 安全静养**，回来时伤势按离线时长好转。

### §2.2 资源加速疗伤（辅，可选）

不想等？可以花银两或用疗伤丹**加速**恢复。这给银两添了一个新的消耗出口，但完全可选——你不点它，挂机一样会好。

### §2.3 恢复速度：轻伤快、重伤慢

恢复速度**按伤势档位分级**：轻伤挂机几分钟就好，重伤要慢得多（小时级）。中间差距要拉明显，否则分档没意义。

这一档差距正是重伤的分量所在：它逼出一个真实抉择——**停下来养很久，还是带着重伤继续深推、拿寿元去赌**。

再叠一个次要的**境界修正**：修为越高，自愈略快（内力护体），呼应武侠里「内功深厚者恢复得快」。境界只是微调，主导恢复速度的仍是伤势档位。

> 具体分钟数待 sim 标定（§6）。

### §2.4 恢复机制顺便解掉了「死亡螺旋」

「受伤只在失败时产生」有个隐患：会不会陷入「败→变弱→败得更惨→更重伤」的不归路？

自动疗愈就是这个安全阀：输了受伤，但挂机一会儿自动养好，不会越败越弱地滑向深渊。真正会把伤累积成重伤、乃至折寿的，只有**不肯养伤、硬着头皮连续强撼同一堵墙**的玩家——那是他主动选择的赌命，不是系统逼他。恢复机制因此既兜住了螺旋，又保住了「战死」的张力。

## §3 伤是什么：三类伤，各压不同的地方

三类伤**共用同一套「轻/中/重 + 自动疗愈」的框架**，所以玩家不用管三套计时器、不会被 debuff 刷屏；但它们**各自压不同的属性**，所以每一类都有真实、可辨的后果。

首发三类：

| 伤型 | 叙事 | 战斗影响 | 修炼影响 |
|---|---|---|---|
| **外伤** | 皮肉筋骨之伤 | 防御 ↓、血上限 ↓（更脆，更扛不住打） | 轻微（痛得难以入定） |
| **内伤** | 经脉气血受损 | 攻击 ↓ | **最重**（伤在修炼的根子上） |
| **毒伤** | 余毒未清 | 命中/闪避 ↓ | 中等（运功须分心镇压） |

**三类伤都会拖慢挂机内力产出，只是轻重不同**。这一笔让受伤的代价溢出到战斗之外——带着伤挂机，连修炼都慢半拍。它把受伤从「一个战斗 debuff」升级成「你整个人的状态」，分量重得多。

拖慢的幅度按武侠逻辑分级：修炼靠的是经脉运行气血，所以**内伤**伤在根子上、拖得最狠；**毒伤**要分心镇压余毒，居中；**外伤**只是痛得难以入定，最轻。多种伤并存时按乘法叠加，并设一个地板，避免同时带三种重伤直接把修炼归零。

### §3.1 伤型是一张可扩展的表

三类伤不是写死的。**每一类伤是一行配置**（叙事名 + 压哪些属性 + 恢复档偏移），底层机制骨架不关心具体有几类。日后要加「惊惧」「走火入魔」「寒毒」，只是往表里加一行，不改任何机制代码——沿用项目里「地图 ID 单一数据源」「路线穷尽检查」那套数据驱动的风格。首发只填内/外/毒三行。

## §4 伤有多重：三档 + 一条致死线

每种伤型内部分**轻 / 中 / 重**三档，重度之上还有一条**致死线**。

**升降都在同一条严重度轴上**（不搞叠层）：

- 带着「外伤·轻」再次惨败于硬仗 → 升「外伤·中」→ 再败 → 「外伤·重」（开始折寿，见 §5）→ 再败越过致死线 → 强制转世；
- 养伤则一档档回落：重 → 中 → 轻 → 痊愈。

这样整套受伤的动态一句话就能说清：**硬仗失利推高伤势、养伤拉低伤势、越过重度开始折寿、越过致死线强制转世**。玩家看一眼「外伤·中」就全懂，不用去数「几层几伤」。

## §5 伤到极致会折寿：与转世系统的接口

这一节是受伤系统向转世系统暴露的正式接缝，对应 `reincarnation/design.md` §9 预留的接口行。

**只有重度及以上的伤才折损寿元**，轻伤中伤不碰寿元：

- 轻伤、中伤：纯粹的战斗 debuff，挂机养好即可，和寿元无关；
- **重度**：开始折损寿元，越重折得越多；
- **致死线**：伤势越过此线 → 当场不治，触发**强制转世**（按六折结算声望，见 `reincarnation/design.md` §3.1）。

这样三个系统严丝合缝、各管一段：

```
日常轻中伤  →  受伤系统自理（战斗 debuff + 自动养）
重度伤      →  接入寿元（开始折寿）
致死线      →  接入转世（强制转世）
```

玩家的决策链因此非常清晰：「我伤到重度了，再撑下去要折寿、甚至送命——是停下养，还是赌一把继续深推？」这正是我们想要的、由玩家主动承担的赌命张力，而不是系统强加的惩罚。

**接口约定**：受伤系统对外输出一个函数——「给定当前伤势，返回寿元折损量（重度以下为 0，重度及以上随严重度递增）；伤势达致死阈值时，返回强制转世信号」。

## §6 待 sim 标定清单

| 待标定项 | 说明 |
|---|---|
| 各档恢复速度 | 轻/中/重的恢复分钟数，轻重差距要拉明显 |
| 境界恢复修正 | 修为对自愈速度的加成幅度（次要项） |
| 各伤型压属性幅度 | 已标定：战力压制 轻 10% / 中 25% / 重 45%（sim 扫描：再往上加，带伤作战变纯亏，「带伤打还是养伤」的权衡反而消失） |
| 各伤型压内力产出量级 | 已标定：在战力压制基础上按伤型加权——内伤 75% / 毒伤 45% / 外伤 25%，多伤乘法叠加、产出地板 40% |
| 重度折寿量 | 重度及以上每档折损多少寿元 |
| 致死阈值 | 越过多少触发强制转世 |
| 硬仗受伤判定 | 惨胜的「低血」阈值、败战给几档伤 |
