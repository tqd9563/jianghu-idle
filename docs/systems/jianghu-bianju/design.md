## §0 解决什么问题

玩家在江湖里只有一种身份：打手。所有动作都为战力，战力只为推关；卡关时退回前一关挂机刷掉落，仍是战斗。编年让江湖自己在动，但玩家只是读者：世界变了，能做的事没变。

本系统让江湖里的事找上玩家，由玩家做选择，后果写回江湖，也写到后世。

**样张结论**（2026-11-17）：六条样张用户都认可，最中意第三条（前世所为找上门）与第六条（小人物的故事，有后续）。所以内容以「有人、有后续」的事为主。

## §1 裁决

| # | 裁决 | 理由 |
|---|---|---|
| J1 | 事件挂在玩家本来就在做的事上，不新增「为了触发事件而做」的动作 | 卡关时玩家在刷掉落，另开一件事就成了二选一 |
| J2 | 事不过期，出现后一直等玩家处理 | 放置游戏不能要求玩家常回来看 |
| J3 | 生活技能不立独立系统；医、铸、渔这类行当先作为事件的内容出现 | 人同一时间只做一件事，它就要和刷掉落比价；另开一槽并行，它就是又一个计时器。总坛上线、丹药与疗伤有了需求后再评估 |
| J4 | 首批内容向跨世因果与故事型奇遇倾斜 | 样张结论 |
| J5 | 承袭上一世名号时，它就是本世名号，不再另起；没有承袭的照旧 | 现行名号一世只起一次；`../../rules/copy/chronicle.md` §1 随实装改 |
| J6 | 事件里不在名册上的无名小人物，可以有一则三句以内的故事；名册人物仍只有名号加一句话人设 | 故事型奇遇要用；宪章 §9 已随 v1.5 修订 |
| J7 | 不设每世件数上限，密度交给触发门槛 | 触发本身就有门槛；sim 与自测时统计每世实际件数，过密再加 |
| J8 | 事件的奖励只给东西与门路（残页、装备、因缘、名号），不新开货币，阅历不解冻 | 新货币要配去处、要重拟合节奏；阅历随 BACKLOG「银两与阅历的长线定位」一起定 |
| J9 | 首批只做卷一至卷三 | 先自测体验，通过后按卷补 |

## §2 硬规则

1. 按进度或江湖历触发，不按现实时间过期。
2. 离线时触发的事等玩家回来处理（§4.2）。到一世终了仍未处理的，按「不作为」了结：每件事都有一个不作为的选项，它不带惩罚。
3. 给机会多、罚得少。代价只出在玩家自己选的选项里，挂机中不随机扣东西。
4. 不设每世件数上限（J7）。编年的条数仍守现行口径（`../living-jianghu/design.md` §2.4），小事不进编年。
5. 效果只走 §4.3 的固定挂点；单件影响设上限，并进节奏守卫。

## §3 事件分类

| 类 | 是什么 | 样张 | 改数值 | 能否重复出现 | 写作成本 |
|---|---|---|---|---|---|
| 跨世因果 | 前世做过的事，后世有人找上门 | 三 | 改 | 能：骨架固定，人与事取自名册和前世事实 | 低，一副骨架用很多次 |
| 故事型奇遇 | 挂在某张图上的一则小人物故事，可分两三段 | 六 | 改 | 不能：了结后不再出现，结局记成事实 | 高，一则只用一次 |
| 规则型奇遇 | 一个情境加一次小判断 | 一、二 | 改 | 能：每世可遇 | 中 |
| 江湖大事 | 名册推演出的势力冲突，挂一个全局标签，玩家可以站队 | 四 | 改 | 能：换势力、换事由 | 低 |
| 岁时小事 | 年岁与节令的一笔闲文，拿前世记录作对照 | 五 | 不改 | 能 | 低 |

**事实接力**：战斗与故事的结局都记成事实（编年已按世存事实，`../living-jianghu/design.md` §2.4），跨世因果的骨架读这些事实。故事的「后续」不另写脚本，由下一世的因果骨架接上。

**内容量**：100 天约 33 世，每世件数不设上限（J7），总次数待 sim 统计。能重复的四类靠「骨架 × 名册填空」撑住。故事型按图挂、一图至多一则，随推图进度出现，不必每世都有。

## §4 触发、待处理与效果

### §4.1 触发源

事件只能用下面这些条件：

- 某张图累计挂机的场次；头一回进入某图、某卷；
- 击败某个岗位上的人；拜入门派、地位升级；
- 年岁节点、节令；
- 伤势状态；一件兵器随身打过的场次；
- 江湖历某年名册推演出的势力大事；
- 前世事实：击败过谁、拜入过哪家、了结过哪则故事。

出哪件事由世界种子、世数与触发点确定性地算出，sim 可以复现。

### §4.2 待处理的事

- 一件事触发之后、玩家做出选择之前，叫**待处理**。它不打断挂机，也不过期，一直等到玩家来选。
- 在线与离线结算都会判定触发，所以离线回来时可能有几件待处理的事。
- 同时待处理几件先不设上限，与 J7 同一个口径：自测时看离线回来平均堆了几件，堆多了再加。
- 岁时小事没有选项，不算待处理，出现即了结。
- 一世终了仍待处理的，按不作为了结（§2 第 2 条）。

### §4.3 效果挂点

事件只能改下面这些。各挂点的上限与对里程碑的影响待 sim。

| 挂点 | 例 |
|---|---|
| 伤势 | 消去或加重一档 |
| 某势力守关人强弱 | 本世强一档或弱一档 |
| 某图、某势力的掉落 | 本世倍率 |
| 给一件东西 | 武学残页、装备、银两 |
| 一件装备 | 一条词条的取向、一行来历句 |
| 六隐因缘 | `../wudao-yuanliu/design.md` §3 |
| 名号 | 承袭上一世（J5） |
| 追加一场战斗 | 对手取名册在任者 |
| 事实 | 只供后续事件作条件，不直接改数值 |

## §6 界面约束

入口与版式在原型阶段定，原型获批后才实现。已知约束：

- 事件不打断挂机；有待处理的事时入口才出现，带金点。
- 选项只写动作，不预告后果。
- 正文称「你」，用词守 `../../rules/copy/battle-narration.md` §0；编年条目仍用第三人称（`../living-jianghu/design.md` §2.4）。

## §7 验收（草案）

1. 全新存档连玩三世：每世遇到至少 2 件要做选择的事；第二世起至少 1 件出自前世所为。
2. 离线 24 小时后回来：没有一件事因为不在线而错过或受罚。
3. 关掉本系统与开着对照：里程碑首达天数的差在节奏守卫容差内（各挂点上限待 sim）。
4. 自评两问，预先登记：读完想不想知道后续；有没有觉得自己不只是打手。

## §9 开放问题

- 故事型奇遇了结后，后世要不要在原地留一点痕迹，还是全交给因果骨架。
- 「认药」这类靠玩家本人记住答案的事，后世再遇要不要换题。
- 仇杀、侠客（BACKLOG 簇 C）是否并进因果骨架。
- 门派差事途中出事，是否算一个触发源。
